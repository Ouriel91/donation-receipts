# Local runbook

Run commands from the repository root. The [README](../README.md#setup) covers cloning, installing dependencies, and creating your own OAuth application.

## Offline checks

```powershell
.\.venv\Scripts\python.exe -m src.main --help
.\.venv\Scripts\python.exe -m src.main --mode harness --dry-run
```

A harness run without `--dry-run` writes empty synthetic attachment placeholders under `receipts/harness/` and fixture message entries under `data/processed_messages.json`. These files remain local. The harness does not authenticate or download Gmail attachments.

## Create a local account

Choose a new neutral account label. This example stops if its account directory already exists:

```powershell
New-Item -ItemType Directory -Path accounts/sample_account -ErrorAction Stop | Out-Null
Copy-Item -LiteralPath examples/account-config.example.json -Destination accounts/sample_account/config.json
```

The configuration is optional. `display_name` labels workbook rows. `expected_donor_ids` and `expected_donor_names` enable donor matching; keep any actual values only in the ignored local account directory. No account names or credentials are supplied by this repository.

## Gmail with your own OAuth application

Enable the Gmail API, configure consent for your own use, and create an OAuth client of type **Desktop app**. Follow the [Google Python quickstart](https://developers.google.com/workspace/gmail/api/quickstart/python) for Google Cloud setup. Put your downloaded client JSON at `accounts/sample_account/credentials.json`. Never reuse someone else's credentials or token.

The application requests only `https://www.googleapis.com/auth/gmail.readonly`. An interactive authorization can create or refresh `accounts/sample_account/token.json`. A Gmail dry run still accesses the account:

```powershell
.\.venv\Scripts\python.exe -m src.main --mode gmail --account sample_account --year 2026 --dry-run
.\.venv\Scripts\python.exe -m src.main --mode gmail --account sample_account --year 2026
```

Without `--year` or `--query`, Gmail mode searches `newer_than:7d has:attachment`. An explicit `--query` overrides the query generated by `--year`. The CLI processes one account per invocation; it does not provide scheduling.

## Summary from local PDFs

```powershell
.\.venv\Scripts\python.exe -m src.main --mode summary --account sample_account --year 2026
```

The input is `receipts/<account>/<year>/<NN_Month>/*.pdf`; use the month names generated by the application, such as `01_January`. Supported image attachments can be saved by Gmail mode, but summary scans PDFs only.

The active workbook stays at `reports/<account>/<year>/donation_summary_<year>.xlsx`. An account with no receipts still gets an empty-summary workbook. Close Excel and make a local backup before regenerating an existing report; summary writes the same output path.

The workbook keeps Hebrew RTL month sheets. Confident duplicate groups become one donation row before severity is calculated. A source sheet links all scanned PDFs; a summary sheet separates input-file and donation-row counts. Suspected or conflicting duplicates remain separate for human review.

`ready`, `warning`, and `critical` are review classifications. Missing core fields remain critical; from 2026 onward, a missing tax reporting number alone is a warning requiring verification. These rules do not determine tax eligibility. See the README for the full extraction and consolidation behavior.

## Reprocessing and rebuilding

`--reprocess` revisits matching Gmail messages already in the manifest and can create additional suffixed files. `--rebuild` deletes the selected local receipt-year directory before Gmail processing and implies `--reprocess`. Both require a deliberate Gmail operation; neither is needed to regenerate a summary after an extraction change.

## Private output layout

Use one active workbook in each `reports/<account>/<year>/` directory. Put manual backups and baselines in `_archive/`, and local diagnosis or QA files in `_qa/`. These are storage conventions; summary does not automatically create backups or QA reports.

Whole account, receipt, report, secret, and runtime directories are ignored by Git. Generic configuration examples live in `examples/`. Keep real PDF text, donor data, OAuth exports, workbooks, and console output containing private information out of issues, AI prompts, and commits. Check staging explicitly before sharing changes.
